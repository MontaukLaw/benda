# 20通道上位机与日志

运行 `main.py`，在右侧“波形设置”选择串口并连接。左侧仅显示 Raw/Baseline、Signal、Fast K/Slow K 图；右侧为监控、波形设置、三参数、串口日志、固件升级 Tab。上位机不加载或连接电机/CAN。固件升级按钮保留给用户手动操作，开发验证只编译固件，不自动烧录，也不打包 EXE。

传感器监控连接期间自动记录，无需点击开始。滚动日志位于本目录的 `recordings/rolling/roll_*.jsonl`；每次启动有独立会话名，断开/重连写入连接事件。DFU 使用独立升级连接，其过程显示在升级页，不属于监控日志。

- `kind=frame`：包含未经筛减的完整 `frame`，包括 Raw、Baseline、Signal、状态、Fast/Slow K、温度、参数与命令回读等实际收到的字段。
- `kind=rx/tx`：`hex` 是原始收发字节，保留未识别内容和不完整帧。多条 RX 按序拼接才能重新解析，不要把一个读取块当作一帧。
- 所有记录带本地时区时间戳、纳秒墙钟/单调时钟、端口和递增序号。`connected/disconnected/serial_error/tx_error` 标记通信边界或错误；`log_gap` 标记后台拥塞造成的丢失。

独立线程完成 JSON 序列化、写文件和清理，每5秒或积累4 MiB写一批。每个文件最多约32 MiB，整个滚动目录保留最新16个同格式文件（约512 MiB），超过后自动淘汰旧文件；手动转存的CSV不参与轮转。生产者队列最多16384条，并有32 MiB估算容量限制，串口原始读取块最多64 KiB；持续磁盘异常时保留当前批次并重试，队列满后丢失计数和日志页告警会明确显示，不无限增长内存、不阻塞接收等待磁盘。旧文件清理失败也会告警，此时容量可能暂时超限。

正常关闭先停接收，再在后台补写，完成后自动退出，界面线程不等待日志写盘。磁盘持续不可写时会提示未保存数量。强制终止/断电可能丢失尚在内存或操作系统缓存的尾部；没有逐条执行磁盘同步。

查看日志时按会话和时间选取连续文件，核对缺口及连接事件，只把 `kind=frame` 内 `type=debug/signal` 计为采样；原始RX、参数回读、温度、慢基线等不能重复计入FPS。Run模式缺少的诊断值不能从日志推断为真实采样，请使用Debug模式记录完整诊断。滚动日志尾部可能有最多约5秒尚在内存，查看实时日志前须考虑这一延迟。

原有“转存最近1/3/5分钟”继续保留，生成 `recordings/recent_1min.csv` 等固定快照和对应 `.meta.json`（范围、完整性、SHA256）。这些文件只有点击转存才更新；分析指定快照时先核对元信息，不能当成持续刷新的日志。历史缓存容量有限，导出元信息会标记不足五分钟等情况。
