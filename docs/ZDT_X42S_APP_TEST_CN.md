# ZDT X42S 上位机通信测试

> 本文为电机驱动手动测试说明；手动脉冲参数不决定监控页的寻压策略。当前监控寻压和自动标定使用[压力反馈控制](../PRESSURE_FEEDBACK_CONTROL_CN.md)中的共享参数及有效学习表，见[当前实现](../CURRENT_SYSTEM_CN.md)。

App 默认选择 ZDT X42S。`PY_SRIPT/algo_monitor/motor_connection_config.json` 独立保存型号和新电机连接参数，不修改旧电机的 `motor_control_config.json`。

```json
{
  "motor_model": "zdt_x42s",
  "zdt_x42s": {
    "interface": "gs_usb",
    "channel": 0,
    "bitrate": 500000,
    "node_id": 1,
    "timeout": 0.2,
    "temperature_positive_sign": 0
  }
}
```

使用旧 PD42S1 时，只将 `motor_model` 改成 `pd42s1`，重启 App。新电机模式禁止旧电机连接入口和后台通信，旧的运动/压力控制不能驱动新电机。配置缺失默认新电机；配置错误则停止电机通信并显示错误，不猜测型号。打包运行时读取 EXE 同目录的配置文件。

## 文档核对与接线设置

- Emm速度细分：手册第19页`S_Vel_IS`及第81页§5.6.11支持0.1 RPM命令单位；驱动每条`FD`运动前发送`4F 71 00 01`并确认成功，不写Flash。速度字上限按第57页3000保守限制，因此细分范围0.1～300 RPM；更高速度仅接受整数，确认静止后以`4F 71 00 00`切回1 RPM。所有相对/绝对位置命令共用换算，回位24 RPM不会变成2.4 RPM。单位配置应答失败不发运动命令，运动应答丢失不重发。第71及97～98页的Emm速度反馈仍按整数RPM解释，不除以10；第103页配置读取未包含该开关，因此以写配置应答确认，不声称读取到了该项。此命令仅对已识别的Emm使用，禁止用于X固件。
- `ZDT_X42S第二代闭环步进电机用户手册V1.0.5_260527.pdf`：第18页给出 CAN 默认 500000 bit/s、固定校验 0x6B、Response 默认 Receive；第75页给出默认地址1。USB适配器类型由电脑端硬件决定，不是电机厂家规定的接口。
- 手册第42～43页：扩展帧 ID 为 `(地址 << 8) | 分包序号`，序号从0开始，每包首字节重复功能码，其余最多7字节。例如地址1读取状态：ID `0x0100`，数据 `43 7A 6B`。
- 电机通讯端口复用需选择 `CAN1_MAP`，CAN速率与配置一致，`Checksum=0x6B`，`Response=Receive` 或 `Both`。CAN H/L接线与终端电阻按手册第28页检查。
- `ZDT闭环步进电机MODBUS协议使用说明V1.0.1_260818.pdf` 第6～7页描述 RS485 的 Modbus RTU（115200、8N1，需改 Checksum 为 Modbus），还规定 X 固件32位寄存器数据先低字后高字。此规则不能直接用于自由协议 CAN。当前实现是 CAN 自由协议，不实现 RS485/Modbus，也不自动修改电机协议配置。

## candleLight USB适配器

当前设备为 `candleLight USB to CAN adapter`（VID:PID=`1D50:606F`）。新电机默认使用 `interface="gs_usb"`、`channel=0`（第一个USB CAN设备，必须写JSON整数0），不使用PCAN接口。旧PD42S1的PCAN配置不变。若新电机改接真正的PEAK适配器，可将新电机配置改为 `interface="pcan"`、`channel="PCAN_USBBUS1"`。

依赖安装：`py -3 -m pip install -r PY_SRIPT/requirements.txt`。Windows需要WinUSB设备驱动，以及Python依赖`gs-usb`、`pyusb`、`libusb-package`；程序通过PyUSB加载依赖包中的libusb DLL，不修改系统PATH。本机已确认WinUSB正常，不需要替换设备驱动。参考 [python-can candleLight接口说明](https://python-can.readthedocs.io/en/main/interfaces/gs_usb.html) 和 [libusb-package](https://github.com/pyocd/libusb-package)。

“无法打开 candleLight USB CAN”指USB设备打开失败，检查连接、序号、驱动或其他程序占用；“CAN适配器已打开，但电机响应超时”则是电机总线问题，检查供电、CAN H/L、终端电阻及电机参数。修改JSON或安装依赖后需重启App。

## 已实现的测试功能

“新电机控制测试”页提供连接/断开、使能、失能、触发编码器校准，以及Emm普通相对位置测试。启动按所选型号自动尝试连接，新电机连接只读状态，不自动发送使能或运动命令。

右上角使用大号数字显示实时位置、相电流、驱动板温度和转速，单位固定在各数值标题中；窄窗口自动换行到顶部说明下方。面板同步显示实际刷新频率，数据过期时标灰并注明为上次读数，断开后清空数值。其余诊断信息保留在下方实时反馈区。

### Emm下压/抬起测试

- 下压按钮发送CCW（逆时针、方向字节01）；抬起按钮发送CW（顺时针、方向字节00）。首次小角度核对机械安装后的运动方向。
- “移动脉冲数（相对）”直接输入正整数脉冲数，原值写入手册第57页普通位置命令FD；运动模式02，从当前实际位置起算，同步标志00。不是绝对坐标，也不经过角度换算或取整。
- 默认16脉冲、速度10 RPM、加速度档位100。在1.8°、16细分配置下，16脉冲对应1.8°；一个指令脉冲对应0.1125°。界面输入范围1～2147483647脉冲。速度输入按电机“速度缩小10倍”功能关闭时解释。
- 加速度输入0～255是档位：0直接起动；非零时，每隔`(256-acc)×50µs`变化1 RPM，数值越大加减速越快。不是旧电机的r/s²单位。
- 每圈脉冲数默认3200，仅用于显示参考角度，不改变发送脉冲数或电机细分；参考值应匹配电机步距角及细分：`360÷步距角×细分`。例如1.8°、16细分为3200，0.9°、16细分为6400。不得使用65536反馈counts作为每圈指令脉冲数。
- 页面同时显示发送脉冲数及参考转角。例如输入44脉冲，在3200脉冲/圈下对应4.95°；调整每圈脉冲数只影响参考转角。
- 所有测试输入框仅显示数字，单位放在框外；隐藏上下微调按钮，禁止鼠标滚轮改值，包括输入框已聚焦时，保留键盘输入。
- 下压/抬起仅在新鲜Emm状态、已使能、编码器及校准表就绪、无堵转/保护标志且转速为0时开放；后台发令前再次读状态核对。回执只表示命令已接收，完成情况看实际位置、转速和到位状态。
- `Response=Receive`只确认接收，`Both`还会在到位后主动返回`FD 9F 6B`。当前App主动查询状态判断到位：空闲每2秒，手动运动期间按50毫秒目标间隔查询，学习/控制任务自行快速读取。尚未将主动到位报文接入独立完成流程；不要设置为仅`Reached`，否则缺少接收确认会报错或超时。手册到位窗口默认0.8°，实际配置尚未读取，到位标志不代表误差严格为零。
- “立即停止”发送手册第60页`FE 98 00 6B`，保持使能，不以失能松轴代替停止。停止请求优先于等待发送的运动命令，并取消尚未发送的位置命令；正在执行的CAN事务结束后发送停止。通信失联时不能保证远程停止成功。
- 运动命令不自动重发，避免超时造成重复位移。手动位置运动切换为快速查询，确认停止后回到2秒空闲查询；测试页没有自动压力控制或机械行程限位。输入仅用于当前会话，重启恢复上述测试默认值。

### 多圈无限位碰撞回零

- 点击“读取回零参数”，显示电机保存的方向、速度、超时、碰撞检测转速/相电流/持续时间和碰撞后退让设置。核对机械挡块可承受碰撞及退让，再勾选确认，点击“多圈碰撞回零”。该操作沿电机保存的回零方向运动，与下压/抬起按钮方向无关；只触发模式02，不修改或保存电机参数。
- 后台发送前重新读取参数和状态；参数变化时回填显示并要求重新核对，状态不满足或停止已请求时拒绝触发。动作命令只发送一次，应答超时不重发。
- 回零期间或结果未确认时禁止普通位置运动、再次回零、使能及校准，保留失能和中断入口。“中断回零”发送专用9C命令；在本次回零可能仍进行或反馈正在回零时，“立即停止”先尝试9C再发送普通FE停止。
- 同步显示电机真实的“正在回零”“回零失败”标志。只有本次发令后观察到正在回零，再观察到标志清除、未报告失败/保护且保持使能、转速为0，才显示本次结束；初始空闲不算成功。未采到开始过程、应答丢失或通信间断时不推断成功，可用中断回零解除未确认状态。重连不把先前过程当成本次成功。
- 手册第30页将碰撞位置定义为零点，但第21、91页还规定碰撞后退让卸力：0表示按电流退让，非零为0.1°单位的固定退让。手册未明确不同固件在退让前后清零的时序，所以不能仅凭回零结束断言实时位置严格为0；界面持续显示真实位置，不额外发清零命令或软件置零。碰撞检测也可能因阈值不合适提前触发，须核对实际机械位置。
- 回零参数和按钮在唯一的独立CAN线程执行，GUI不等待机械回零完成；回零期间快速轮询，停止后恢复2秒空闲查询。新增回零功能仅用模拟CAN验证，未主动触发实机碰撞回零。

校准会正转一圈再反转一圈，需空载且确保行程安全；按钮前需勾选空载确认。成功应答仅表示收到命令，不能作为本次校准完成的判断。写命令超时不自动重发。失能会松轴。断开和退出仅关闭CAN连接，不改变电机使能状态。

后台只使用一个CAN线程和一条连接。空闲每2秒查询一组系统状态，读取温度、电流及保护信息；位置、速度等随同一系统状态帧返回，不额外查询位置。手动运动、回零、校准和停止确认期间按50毫秒目标起始间隔查询；学习/控制任务独占同一线程，由自身控制循环实时读状态，外层空闲轮询不与其交叉。任务结束或手动运动停止后自动降频，操作队列可以立即唤醒，不等待2秒才响应按钮。

Emm温度需单独命令，最多每2秒补读一次，期间保留真实温度采样时间；每次状态查询仍取得新的位置、电流及过流/过温标志。状态时间戳取系统状态读取完成时刻，不因温度读取或缓存而刷新。X固件温度已在系统状态内，无需补读。Emm汇总帧没有总线电流，明确显示未提供。

界面刷新不发送CAN查询。空闲显示及提交任务使用2.5秒反馈有效期，运动显示使用0.5秒；发令前及任务内仍按新鲜反馈核验，连续轨迹的0.15秒要求不变。空闲学习表恢复允许正常2秒采样间隔，旧缓存不会冒充新样本。读取失败后标灰并禁止使能/校准，保留停止/失能入口；通信恢复后更新状态。空闲期间新发生的状态变化需等下一次查询才显示，电机自身保护独立于电脑查询。

温度符号需留意文档差异：第72页单读温度（Modbus第33页也相同）规定00负、01正；第96页X汇总状态规定00正、01负，并示例`00 22`=34℃。此前按单读章节解释，导致当前实机`00 19`显示为-25℃。现针对当前电机统一采用00正、01负，`00 19`显示25℃，`01 19`仍显示-25℃，不使用绝对值掩盖负温度。JSON默认 `temperature_positive_sign=0`，仅作用于Emm单独温度读取；其他固件确实采用相反定义时可配置为1。页面显示所用符号规则和原始字节。

## 验证与范围

### 2026-09-17 CAN 关闭与重连修复

当前运行环境为 python-can 4.6.1、gs_usb 0.3.1。上游 GsUsbBus 关闭时还会扫描并重新启停设备，且没有显式释放 PyUSB 资源；初始化中途失败也可能留下未清理对象并打印 `GsUsbBus was not properly shut down`。新电机采用本地 `gs_usb_transport.ManagedGsUsbBus`：关闭时停止当前控制器并释放 USB 接口/句柄，不再扫描、启动其他实例；初始化失败也执行清理并保留原始错误。打开失败会记录原始异常，服务线程也在替换旧实例前关闭它。

`tools/test_gs_usb_transport.py` 使用真实 python-can 初始化代码和模拟 USB，覆盖连续 10 次重连、设备缺失、初始化失败、关闭失败及重复关闭；界面测试覆盖连接失败后恢复、连续断开重连及没有运动命令。测试不访问实机。

毛刺已通过独立诊断定位：CAN 关闭或只打开不查询时，20 秒内串口接收错误和异常帧均为 0；CAN 查询时捕获 82 次 CE_OVERRUN，独立进程查询同样捕获 82 次，证明存在解析前的串口接收溢出、丢字节。两路设备当时共享外接 USB Hub 链路，用户随后将 USB-CAN 改为单独 USB 口直插 PC，确认毛刺消失。保持该接法，避免与高速传感器串口共用原来的 Hub 链路。资源清理警告和本次接收溢出是两个问题。完整原始数据与结论见 `analysis_outputs/can_serial_20260917_163013/REPORT_CN.md`；换口后恢复来自用户实机反馈，未另行记录换口后的错误计数。

`py -3 -m unittest discover -s tools -p test_zdt_motor.py -v` 验证文档示例解析、CAN分包和过滤、错误/超时、命令内容、空闲2秒及运动快速查询、温度限频、单线程独占、发令前状态保护和失效恢复。`tools/test_monitor_startup.py` 覆盖完整窗口启动；`tools/test_motor_selection.py` 覆盖新旧型号和无效配置。

现已增加独立Emm位置测试，不接入旧电机压力自动控制，不更改传感器固件，不构建EXE。运动验证使用模拟CAN，覆盖方向、两帧分包、相对当前实际位置模式、角度换算、超时不重发、后台状态拦截及停止取消待发命令，未主动进行实机运动。

此前已在本机使用candleLight/WinUSB成功打开适配器并读取地址1的Emm固件电机状态（电压约23.5V、相电流约6～7mA），连续30组全部成功，实测9.97Hz，单组读取最长10.77ms。实机曾返回温度原始字节`00 19`，现按修正后的符号规则解释为25℃。
